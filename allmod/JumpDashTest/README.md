# JumpDashTest v3 — тестовый мод (UE4SS / Palworld)

Тестовая проверка механик перед интеграцией в основной мод.

## Что изменилось в v3 (по итогам полевого теста v2)

1. **Убран нативный хук `PalCharacterMovementComponent:Jump` — он ломал прыжок.**
   Симптом «прыжок перестал вовсе работать» после хот-релоада мода:
   UE4SS снял старый хук с горячей нативной функции (`Unregistering hook
   by id 'Jump#87'`) и функция осталась мёртвой до перезапуска игры.
   В v3 нативных хуков на движение **нет вообще**.
   ⚠️ **После установки v3 полностью перезапусти игру** — убитая в прошлой
   сессии функция прыжка лечится только перезапуском процесса.
2. **Нативные хуки пассивок заменены на BP-хуки HUD-виджета игрока**
   `WBP_PlayerSideInfo_Separated` (`OnStartPassiveSkill` / `OnEndPassiveSkill` /
   `OnUpdatePlayerEquipment`) — это script-хуки (тот же механизм, что хук
   чата и хук рывка, которые работают стабильно). Виджет сам подписан на
   делегаты `PalPassiveSkillComponent` — дампы это подтверждают.
3. **Конфиг: `Scripts/config.lua` (Lua) через `require`** — конвенция UE4SS,
   как в PalWarpUltimateTeleport / LessRestrictiveBuilding. Работает при
   любом имени папки мода ('aaa', 'JumpDashTest', ...). `config.txt` удалён.
4. **Исправлен `NotifyOnNewObject`**: требует полное имя `Пакет.Класс` —
   теперь `BP_ActionAirDashBase.BP_ActionAirDashBase_C` (в v2 регистрация
   падала с «must contain at least two parts»).
5. **Самоисцеление после хот-релоада**: множитель пояса переподтверждается
   при каждом событии (слот в карте движка именован нашим флагом —
   перезапись безопасна), снятие ботинок принудительно возвращает
   `JumpMaxCount` к ванили. Хот-релоад мода при надетых предметах больше
   не оставляет «прыжок в космос».
6. Опросов/циклов нет: в простое мод не выполняет ни одной инструкции.
   После смены экипировки — два одиночных отложенных перепроверки
   (0.4 с / 1.5 с, `ExecuteWithDelay`), чтобы поймать позднюю репликацию
   пассивок. Это одиночные таймеры, привязанные к событию, не цикл.

## Что делает

| Пассивка | Предметы (ID) | Что меняем | Ваниль | Как |
|---|---|---|---|---|
| `AirDash` (104) | Air Dash Boots (`Accessory_AirDash1..3`), Air Walker Mk-I/II/III/EX | **дистанция** рывка (Ctrl в воздухе) | 400 см / 0.5 с | `Const_MoveDistance` в `BP_ActionAirDashBase:OnBeginAction` |
| `JumpCount_Increase` (81) | Double/Triple/Quad Jump Boots, Air Walker | **число доп. прыжков** | +1/+2/+3 | `CharacterMovement.JumpMaxCount` |
| `JumpPower_Increase` (80) | Anti-Gravity Belt (`Accessory_JumpPower_Increase`) | **силу (высоту) прыжка** | +25% | `SetJumpZVelocityMultiplier("JumpDashTest", x)` |

У Jump Boots меняется только количество прыжков — отдельной высоты доп.
прыжка в игре нет. Высоту меняет пояс (пассивка `JumpPower_Increase`).

Эффект «пружины» у рывка сохраняется: кривая рывка не меняется, при
увеличении дистанции пропорционально растёт скорость (x10 = 40 м за те же
0.5 с). Импульс сохраняется в конец рывка — разгон продолжится планером.

Проверка строго **по пассивке** (`HasSkill` по компоненту пассивок игрока):
работает для любых предметов с пассивкой — ванильных или тех, которым
пассивку выдал другой мод. Нет пассивки → мод ничего не меняет.

## События (весь «движок» мода)

```
ClientRestart                            -> привязка к игроку (1 строка лога)
WBP_PlayerSideInfo:OnUpdatePlayerEquipment -> надел/снял предмет (+late-проверки)
WBP_PlayerSideInfo:OnStartPassiveSkill     -> пассивка появилась
WBP_PlayerSideInfo:OnEndPassiveSkill       -> пассивка исчезла (+принудительный откат прыжков)
BP_ActionAirDashBase:OnBeginAction         -> параметры рывка (1 регистрация:
                                              загрузка -> ClientRestart -> NotifyOnNewObject)
PalUIChat:OnReceivedChat                   -> команды !jd (тест)
```

Нативные хуки: только `ClientRestart` (используют все моды, безопасен) и
`PalUIChat:OnReceivedChat` (то же). Всё остальное — BP script-хуки.

## Установка (замени старые файлы мода 'aaa' целиком)

```
Pal/Binaries/Win64/Mods/aaa/enabled.txt
Pal/Binaries/Win64/Mods/aaa/Scripts/main.lua
Pal/Binaries/Win64/Mods/aaa/Scripts/config.lua
```

Имя папки может быть любым — конфиг ищется через `require` относительно
`Scripts/`, от имени папки не зависит. Старый `config.txt` удали.
**Затем полностью перезапусти игру** (не хот-релоад).

## Конфиг — `Scripts/config.lua`

```lua
local config = {
    Enabled            = true,  -- false = возврат к ванили
    Debug              = false, -- подробный лог (!jd debug переключает на лету)
    AirDashDistanceMult = 5.0,  -- 1.0 = ваниль (4 м); 10.0 = 40 м
    AirDashTimeMult     = 1.0,  -- 1.0 = ваниль (0.5 с); 0.5 = вдвое резче
    ExtraJumpCount      = 5,    -- доп. прыжки (Jump Boots)
    JumpPowerMult       = 2.0,  -- сила прыжка (пояс); высота ~ x^2
}
return config
```

## Команды в чате

```
!jd            — статус (пассивки, значения, счётчики событий, хуки)
!jd dash 10    — множитель дистанции рывка
!jd time 0.5   — множитель времени рывка
!jd jumps 8    — число доп. прыжков
!jd power 3    — множитель силы прыжка
!jd on/off     — вкл/выкл (мгновенный возврат к ванили)
!jd skills     — дамп всех активных пассивок игрока
!jd save       — записать текущие значения в config.lua
!jd reload     — перечитать config.lua
!jd debug      — вкл/выкл подробный лог
```

## Чеклист теста

1. Полный перезапуск игры → вход в мир. В консоли: одна строка
   `привязка к игроку`, одна `хук рывка зарегистрирован`, `config.lua загружен`.
2. **Прыжок работает вообще без модификаций** (пустые слоты) — проверь первым.
3. Пояс: прыжок выше; снял → следующий прыжок обычный.
4. Ботинки: доп. прыжки; снял → при следующем событии откат.
5. Дэш: Ctrl в воздухе; снял → микро-рывок.
6. Хот-релоад мода при надетых предметах → снятие всё равно откатывает.
7. Пришли вывод `!jd` и `!jd skills` (в ботинках/поясе) — по счётчикам
   (`экипировка N | пассивка start N | end N`) видно, какие события реально
   приходят; от этого зависит, что оставить при интеграции.

## Известные ограничения

- BP-хуки виджета — клиентские (HUD). На выделенном сервере UE4SS их нет;
  для серверного варианта вернулись бы к хукам компонента пассивок.
- Если `JumpMaxCount` игрой не используется для доп. прыжков, количество
  не изменится — `!jd` покажет значение, скажешь — переключим на правку
  `Value` в `SkillInfos`.
- Верховая езда: `JumpMaxCount` при езде не трогаем (у маунта своя логика).
