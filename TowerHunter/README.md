# TowerHunter — трекер и автооткрывалка Ancient Ruins / Ancient Towers (Palworld, UE4SS Lua)

Мод для мини-башен **Ancient Ruins (Ancient Towers)**, разбросанных по карте:
те самые, что закрыты барьером и открываются мини-игрой / разбиванием камней
вокруг / боем с палом, а внутри стоит стела (древний алтарь), с которой
нажатием F берётся награда.

**F6** открывает панель со **всеми башнями мира**. У каждой:

| Кнопка | Что делает |
|---|---|
| **[ ] MARK / [v] DONE** | ваш личный чекбокс «здесь был» — сохраняется в файл между сессиями |
| **TP** | телепорт к башне (со смещением от центра, чтобы не застрять в ней; с ожиданием прогрузки terrain'а) |
| **OPEN** | **нативно** проходит испытание башни любого типа и роняет барьер |
| **LOOT** | **нативно** забирает награду со стелы (то самое «нажать F») |
| **AUTO** | всё сразу: телепорт → открытие → лут |

Сверху общие кнопки: **RESCAN** (пересканировать мир), **AUTO TOUR** —
автоматический обход всех ещё не открытых/не обобранных башен (телепорт →
открытие → лут, одна за другой, останавливается той же кнопкой), **TP
NEAREST** — телепорт к ближайшей незавершённой башне — и **SORT: …** —
переключение сортировки списка: `DIST` (по расстоянию) → `TYPE` (по типу
башни) → `STATUS` (сначала требующие ручного открытия, потом неоткрытые,
потом не обобранные, в конце готовые/помеченные).

### Все типы башен открываются сами — каждым своим нативным путём

Прямой `MarkAsCleared()` на гиммике мини-игры/боя роняет игру (после очистки
код дергает состояние, которого ещё нет — `0x10`), поэтому для них мод
проигрывает **весь путь игрока**, а не только финальный флаг:

- **камни** (`*Destruction*`) — `MarkAsCleared()`: ровно то, что выполняет
  сервер игры после разбития последнего камня (проверено, сохраняется);
- **мини-игры** (`*MiniGame*`: колечко с нажатием F, «зажечь все» одним
  росчерком, угадать точку на круге) — `OnTriggerInteract()` (то, что делает
  нажатие F на пьедестале: игра сама открывает мини-игру) → «победный» вызов
  параметра мини-игры (`OnReceiveGameSuccess` / `OnReceiveSuccessPicking` /
  `OnReceiveMiniGameResult(true)` — то, что виджет вызывает при выигрыше) →
  `OnMiniGameComplete(параметр)` (то, что вызывает HUD после выигрыша) →
  закрытие оверлея мини-игры через его нативный `Close()` (как ESC), чтобы
  ничего не оставалось висеть на экране;
- **бои** (`*PalFight*`) — телепорт приземляет **внутри триггер-сферы**
  (радиус читается из `TriggerSphere.SphereRadius`), бой стартует сам,
  враги спавнятся; затем на каждого врага отправляется его нативный
  `OnPalDead(FPalDeadInfo)` — тот же обработчик, что гоняет игра, когда враг
  реально умирает. Последний «мертвец» сам переводит бой в `Succeeded`,
  стена падает, виджет боя закрывается. Если бой не стартовал за ~6 c
  (триггерная логика серверная и прямой вызов overlap иногда игнорирует) —
  мод нативно «толкает» триггер (`OnTriggerBeginOverlap`), а затем
  воспроизводит собственный переход гиммика в `Succeeded`
  (`OnGameStateChanged`) — тот же обработчик, что выполняет игра при
  победе в бою: стена падает и без самого боя;
- **рычаги** (`*Interact*`) — `EventOnTriggerInteract()`: взаимодействие и
  есть открытие.

`*MANUAL*` в статусе остаётся только для гиммиков, до которых мод вообще не
может дотянуться (не заспавнены / за стримингом — без `RootComponent`).

Статус-текст говорит правду о **стене** (источник истины — флаг барьера
`bLocked`): `WALL UP … | LOOT` — барьер стоит, `WALL DOWN … | LOOTED` —
барьер упал и лут собран; счётчик `2/3` — сколько гиммиков башни очищено.

### Краш 0x338 при «вышел в меню → зашёл в мир» — что сделано

Смещение **0x338** — это поля башенных актёров (у гиммика боя — `bUseLightOrb`,
у стелы — `SpawnedObtainFXComponent`, у гиммика камней — `LightOrbClass`):
краш = чтение такого поля по NULL-указателю на уже уничтоженный объект.
Два известных источника «фантомов», переживающих выгрузку мира:

1. **Оверлей мини-игры** живёт на ПЕРСИСТЕНТНОМ UI-стеке игрового инстанса —
   оставшись открытым при выходе в меню, он тащит мёртвые ссылки в следующую
   загрузку. Теперь мод закрывает оверлей нативным `Close()` сразу после
   победы, а «сторож» закрывает зависшие оверлеи при выгрузке мира.
2. **Виджет боя** (`PalLockGimmickPalFightWidget`) держит слабый указатель
   на гиммик — закрывается `FinishClose()` после победы и сторожем.

Плюс **защита сейва**: мод больше никогда не забирает стелу у НЕоткрытой
башни (лут за закрытым барьером оставляет в сейве противоречивое состояние
«башня закрыта + стела собрана» — тоже кандидат на краш при загрузке).
Сторож раз в 2 с проверяет, что мир загружен; при выходе в меню закрывает
панель, виджеты боя и мини-игр, сбрасывает кэши. Если краш уже «застрял»
в текущей сессии игры — перезапустите игру один раз.

**Одна строка = одна башня целиком.** У башни может быть несколько гиммиков
(например, «каменная» башня — 3 камня, барьер падает только когда выбиты
все): кнопка OPEN очищает их все по очереди, статус показывает прогресс
(`OPEN 2/3`). Гиммики объединяются в башню по точной связи через барьер
(`GimmickObjectIds`) и по близости.

Статус каждой башни читается из игры: `LOCKED/OPEN` (барьер, с счётчиком),
`LOOT/LOOTED` (стела), плюс ваш маркер. Тип башни виден в имени: ROCKS
(камни), MINIGAME (мини-игра), PAL FIGHT (бой), STELA (только стела).

⚠ **OPEN и LOOT работают только вблизи** (по умолчанию до 200 м, конфиг
`ActionRange`). Вызовы нативных функций для башен «за стримингом» роняют
игру (access violation), поэтому для дальних башен используйте TP или
AUTO/AUTO TOUR — мод сначала телепортируется, дождётся прогрузки мира и
только затем действует.

## 1. Установка

Требуется RE-UE4SS (fork Okaetsu) в `Palworld/Pal/Binaries/Win64/`. Скопируйте
папку `TowerHunter` в `Mods/`:

```
Mods/
└── TowerHunter/
    ├── enabled.txt              ← флаг «мод включён»
    ├── README.md
    └── Scripts/
        ├── main.lua             ← логика мода
        └── tower_ui.lua         ← UI (модальное окно на игровых виджетах)
```

Включите мод (`enabled.txt` уже на месте, либо галочка в GUI UE4SS, либо
строка `TowerHunter : 1` в `mods.txt`) и запустите игру. В консоли UE4SS
(Insert → Console):

```
[TowerHunter] progress file: ... (0 marked towers)
[TowerHunter] chat hook attached (PalPlayerState:EnterChat)
[TowerHunter] ready | F6 = panel | !th in chat | in world
```

Войдите в мир и нажмите **F6**.

## 2. Управление

- **F6** — открыть/закрыть панель (при открытии мир пересканируется);
- **ESC** — закрыть панель;
- чат: `!th` — панель, `!th rescan` — пересканировать, `!th stats` — статистика,
  `!th tour` / `!th stop` — старт/стоп авто-обхода, `!th help` — справка.

Список отсортирован по выбранному режиму SORT (по умолчанию — по расстоянию
от вас, ближние сверху), пагинация внизу. Во время AUTO список не
пересортировывается (страницы не «прыгают»), порядок стабилен до ручного
RESCAN/смены сортировки. При открытии панели (F6) она показывает страницу
башни, у которой вы стоите — строка, с которой вы работали, не «улетает».
Цветовая полоса: **золотая** — помечено вами, **зелёная** — башня открыта,
**красная** — ещё закрыта, **фиолетовая** — статус неизвестен.

## 3. Конфиг (начало `Scripts/main.lua`)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `OpenKey` | `"F6"` | клавиша панели |
| `TeleportOffset` | `900` | на каком расстоянии от центра башни вы появляетесь (юниты; 100 = 1 м) |
| `GroupRadius` | `6000` | радиус, в котором стела/барьер/точка ФТ считаются принадлежащими башне |
| `ActionDelayMs` | `1500` | пауза между открытием и забором лута в AUTO |
| `TourDelayMs` | `2000` | пауза между башнями в AUTO TOUR |
| `PageSize` | `7` | строк на странице |
| `GimmickStepMs` | `1000` | пауза между очисткой нескольких гиммиков одной башни (не снижайте: нативные вызовы подряд — риск краша) |
| `FightStartMs` | `6000` | сколько ждать старта боя, прежде чем форсировать нативный `Succeeded` |
| `ActionRange` | `20000` | дальность (юниты; 100 = 1 м), с которой разрешены OPEN/LOOT |
| `ClusterRadius` | `4000` | расстояние, ближе которого гиммики считаются одной башней |
| `ChatPrefix` | `"!"` | префикс чат-команд |

Прогресс чекбоксов хранится в `Mods/TowerHunter/towerhunter_progress.txt`
(ключ — округлённые координаты башни, стабильны между сессиями).

## 4. Как это работает (почему «нативно» и безопасно для ачивок)

Всё делается теми же запросами, что отправляет сама игра, когда игрок делает
это руками — через `PlayerController.Transmitter.Player`
(`UPalNetworkPlayerComponent`):

- **открытие башни** — прямый вызов UFunction `PalLevelObject_LockGimmickBase.MarkAsCleared()`
  (Final/Native/BlueprintCallable, без параметров) — ровно та функция, которую
  выполняет сервер игры после успешной мини-игры/разбития камней/победы в
  бою: ставит реплицируемый флаг `bCleared`, снимает барьер, оповещает
  связанные объекты;
  ⚠ вызывается **только** для гиммиков класса `*Destruction*` («каменные»
  башни): у мини-игровых/боевых гиммиков после `MarkAsCleared()` игра
  обращается к неинициализированному состоянию (нет открытой мини-игры /
  не заспавнен бой) — стабильный краш. Мини-игры и бои проходят свои
  нативные цепочки целиком (см. выше), без `MarkAsCleared`;
  ⚠ почему не «родной» запрос `RequestMiniGameSuccess_ToServer`: его параметр
  имеет тип `TScriptInterface`, который UE4SS не может собрать из Lua —
  указатель интерфейса остаётся NULL, и игра падает с
  `EXCEPTION_ACCESS_VIOLATION reading address 0x0` (проверено на практике);
- **лут со стелы** — `RequestObtainLevelObject_ToServer(стела)` — тот же
  путь, что у статуй-реликвий: сервер сам выдаёт предметы и ставит флаг
  «собрано» в сохранение;
- **точка быстрого перемещения** — НЕ трогается модом: вы жмёте F на статуе
  сами (раньше мод вызывал `RequestUnlockFastTravelPoint_ToServer`; вызов
  убран из соображений безопасности — лишний нативный запрос подозревался в
  краше при перезагрузке мира);
- **телепорт** — `PalUtility:Teleport` + ожидание стриминга мира (стейджинг
  на высоте, трассировка земли, посадка) — проверенная схема PalWarp.

Каждый отложенный шаг проверяет, что мир ещё загружен (игрок в мире): выход
в меню во время AUTO/AUTO TOUR корректно прерывает цепочку, не оставляя
«висящих» таймеров — одна из причин крашей при перезаходе в мир устранена.

То есть достижения, счётчики и сохранение видят действия так, будто вы
пришли и сделали всё сами. Никакой правки памяти/сейвов на прямую.

## 5. Проверка в игре

1. Войдите в мир, нажмите F6 — в списке должны появиться башни. Счёт должен
   совпадать с вики (в текущей версии — 106): «мусорные» кластеры гиммиков
   без стелы/барьера/точки ФТ отфильтровываются.
2. Нажмите TP у любой — вы должны появиться рядом с башней.
3. OPEN у «каменной» — барьер должен исчезнуть (статус станет `WALL DOWN`).
4. OPEN у мини-игровой — мини-игра откроется и тут же закроется победой,
   барьер упадёт. У боевой — бой стартует, враги «умрут», стена упадёт.
5. AUTO на любой закрытой башне — весь цикл целиком.
6. **Проверка сохранения**: откройте башню, соберите лут, выйдите в меню и
   войдите в мир снова — башня должна остаться открытой, лут собранным
   (проверено: флаги живут в сейве). Краша при перезаходе быть не должно —
   если случился, пришлите лог.

При любом падении: в логе перед крашем теперь виден каждый шаг
(`step: MarkAsCleared() ...`, `step: RequestObtainLevelObject(stele)`) — последняя строка покажет, какой
именно вызов не пережила игра. Пришлите лог целиком.

## 6. Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| Панель не открывается по F6 | Смотрите консоль UE4SS; попробуйте `!th` в чате. Проверьте, что вы в мире. |
| Список пустой | `RESCAN`. Если по-прежнему пусто — вы не в основном мире (или версия игры без башен). Пришлите лог. |
| «too far away - use TP or AUTO» | Так и задумано: дальние нативные вызовы небезопасны. Нажмите AUTO — мод сам телепортируется. |
| «SKIP gimmick without RootComponent» | Гиммик не заспавнен (за стримингом) и был пропущен — телепортируйтесь к башне и повторите. |
| «player not found» | Мод загружен до входа в мир — войдите и повторите. |
| `[TP] no surface found` | Башня висит над пустотой/водой — увеличьте `TeleportOffset` и попробуйте снова. |
| Стела «did not react» | Башня была закрыта в момент запроса — повторите OPEN (или AUTO). |
| Мини-игра мигнула на экране при OPEN | Так и задумано: мод нативно «нажимает F», мини-игра открывается и тут же закрывается победой. |
| Башня с `*MANUAL*` | Гиммик не заспавнен/за стримингом — телепортируйтесь к башне и повторите. |
| «[mini-game] did not open» | Игра не успела открыть мини-игру — нажмите F на пьедестале и пройдите её сами (это займёт секунды). |
| «[pal fight] could not be finished automatically» | У этой башни бой не прошёл даже через нативный `Succeeded` — победите сами и возьмите лут. |
| «still locked - OPEN it first» | Лут за закрытой стеной не берётся специально (защита сейва). Сначала OPEN. |
| Краш 0x338 при входе в мир | Причины и фикс — см. раздел про 0x338 выше; после установки этой версии перезапустите игру один раз. |
| «world unloaded … aborted» | Вы вышли в меню во время AUTO/TOUR — цепочка корректно прервана, просто запустите снова в мире. |
| В мультиплеере на выделенном сервере | Мод работает на стороне клиента-хоста; на выделенном сервере серверные запросы могут отклоняться — используйте в одиночке/хосте. |
| Хочу вернуть как было | Просто не пользуйтесь кнопками; уже открытые башни остаются открытыми (это законные флаги сохранения). |

## 7. Технические детали

- Башни находятся в рантайме: `FindAllOf` по классам гиммиков
  (`PalLevelObject_LockGimmickBase` и его BP-наследники), стел
  (`BP_LevelObject_ItemPickupTower_C`), барьеров
  (`BP_LevelObject_TowerLockBarrier_C`) и точек ФТ
  (`BP_LevelObject_TowerFastTravelPoint_C`); компоненты башни связываются по
  близости (`GroupRadius`). Кластеры гиммиков без стелы/барьера/точки ФТ
  отбрасываются (тестовые/осиротевшие актёры — иначе счёт башен завышается);
  стела-сирота показывается отдельной строкой `STELA`. Дамп GObjects подтверждает: level-object'ы
  загружены всегда (те же ~1008 реликвий собираются «на всю карту» в
  Relic Collector).
- UI построен на игровых виджетах (`WBP_PalCommonWindow`,
  `WBP_CommonButton_Activation`, шрифт Palworld) в модальном слое основного
  layout'а — тот же фреймворк, что в Relic Collector.
- Клик-диспетчер — один хук `CommonButtonBase:HandleButtonClicked`,
  подписки по полному имени виджета.
- Все обращения к игровым объектам обёрнуты в `pcall`; мод не пишет в память
  и не трогает файлы сохранений.
- Отладка из консоли UE4SS: глобальная таблица `TowerHunter` —
  `TowerHunter.stats()`, `TowerHunter.state(1)`, `TowerHunter.rescan()` и т.д.
