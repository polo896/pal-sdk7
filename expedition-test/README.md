# ExpeditionHubTest v0.7 — менеджер экспедиций (Palworld 0.4.11, UE4SS Lua)

**F6 — панель. Полный цикл из панели: выбор миссии → назначение палов (вручную из
Palbox или АВТО) → запуск → сбор лута.** Игровой UI станции не открывается вообще.
Не для публикации (тестовая стадия).

## Что починлено в v0.7 (по итогам живого теста v0.6)

Тест v0.6 показал: Palbox-список и сила палов **работают**, список миссий работает,
но выбор миссии падал обратно в краш 0x70. Разбор лога дал три причины — все устранены:

1. **Прямая запись `TargetMissionId` УДАЛЕНА** — именно она крашила игру: запись
   обходила серверный флоу (делегаты, счётчик требуемой стихии) и оставляла станцию
   в полуинициализированном состоянии → 0x70 на первом же чтении/старте после неё.
   Теперь выбор миссии идёт **только** через серверную функцию с архивом.
2. **Починены пути CDO**: в объектной системе UE имена CDO без префикса `U` —
   `/Script/Pal.Default__PalActionTransportItem` (в v0.6 был `Default__U…`, из-за
   чего игра не могла сериализовать имя миссии в архив, и включался злосчастный
   запасной путь). Добавлен запасной вызов через объект класса и живой экземпляр.
3. **Починены хуки**: `RegisterHook` требует двоеточие —
   `/Script/Pal.Класс:Функция` (в v0.5/v0.6 была точка, хуки молча не ставились —
   поэтому в логе не было дампов архива). Теперь неудачи регистрации пишутся в лог.
4. **Гейты состояний**: все действия со станцией (выбор миссии, добавление/снятие
   палов, АВТО, запуск) требуют состояние `Ready` и пишут текущее состояние в лог —
   в v0.6 попытки добавить палов, возможно, отклонялись сервером именно из-за
   состояния станции (в логе это не было видно).
5. **Кнопка «ОТМЕНИТЬ ЭКСПЕДИЦИЮ»** (в режиме НАЗНАЧЕНЫ при state=InProgress) —
   `RequestCancelInProgressMission_ServerInternal`, простые параметры.
6. Пробы формата архива теперь логируют все исходы: GUID+int32
   (`WritePlayerFeedItemTo`) и FName+int32 (`WriteBlackboard(FPalStaticItemIdAndNum)`).

## Панель (F6)

- `<< PREV` / `NEXT >>` — выбор станции (все базы); инфо: состояние, миссия, база,
  палы, сундук, требование стихии, сила команды, % награды.
- Кнопки: **АВТО-ПАЛЫ** · **ЗАПУСК** · **СОБРАТЬ ЛУТ** · **СОБРАТЬ ВСЁ**.
- Блок списка, 3 режима (стрелки `<` `>` в шапке блока; клик по «РЕЖИМ: …» — обновить):
  - **МИССИИ** — экспедиции (сложность, время, сила, стихия×N, макс. палов), ВЫБРАТЬ;
  - **PALBOX** — палы по убыванию силы, «+ ДОБАВИТЬ» (помечены «на экспедиции»/«искл.»);
  - **НАЗНАЧЕНЫ** — состав станции, «− СНЯТЬ»; внизу «СНЯТЬ ВСЕХ», а при идущей
    экспедиции — «ОТМЕНИТЬ ЭКСПЕДИЦИЮ».
- `< СТР` / `СТР >` — страницы списка.

## Порядок теста

0. Сразу после загрузки мира в логе должны быть строки «hook установлен: …»
   (4 штуки). Если «hook НЕ установлен» — пришли лог.
1. F6 → выбери станцию. Посмотри в инфо её **состояние**. Если InProgress/Reward —
   выбери другую станцию в Ready (или собери лут / отмени).
2. Режим **МИССИИ** → **ВЫБРАТЬ** у миссии → в логе: «WriteBlackboard(CDO) ок»,
   «архив миссии (N байт): …», «ГОТОВО: миссия выбрана через архив»?
3. **АВТО-ПАЛЫ** → «ГОТОВО: АВТО назначил палов N → M»? (это подтверждённый путь —
   он должен работать независимо от формата архива палов)
4. Режим **PALBOX** → **+ ДОБАВИТЬ** пала (не «ЗАНЯТ»!) → в логе будут строки
   «[проба GUID+int] …» и «[проба FName+int] …» — пришли их обязательно.
   Затем «раскладка 1 … ГОТОВО»? Если «ни с одной раскладкой» — пришли лог.
5. Смотри «стихия: … n/N» и «награда: X%» в инфо станции → **ЗАПУСК** → InProgress?
6. При Reward → **СОБРАТЬ ЛУТ** → предметы в инвентаре?
7. Перезаходы в мир, открытие/закрытие панели — крашей быть не должно.
8. (Опционально, самый ценный дамп) подойди к станции и сделай в игровом UI:
   выбор миссии + добавление одного пала — в логе появятся «>>> [hook] выбор
   миссии / добавить пала: … архив(N байт): …» — пришли их: это эталон формата.
