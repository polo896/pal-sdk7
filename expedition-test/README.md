# ExpeditionHubTest v0.1 — мод-пробник системы экспедиций (Palworld 0.4.11, UE4SS Lua)

ТЕСТОВЫЙ мод: разведка перед написанием чистого мода-менеджера экспедиций с GUI (F6).
Ничего не делает сам по себе — только отвечает на команды в консоли UE4SS и логирует.
Не для публикации, не для постоянной игры.

## Установка

```
Pal\Binaries\Win64\ue4ss\Mods\ExpeditionHubTest\
    enabled.txt
    scripts\main.lua
```

## Проверяемая гипотеза

Экспедиции = система CharacterTeamMission:

- станция = `UPalMapObjectCharacterTeamMissionModel` (по одной на здание, есть со всех баз);
- состояние `State`: 1=Ready, 2=InProgress, 3=Reward (награда ждёт в сундуке станции);
- удалённый запуск — UI-модель `UPalUIMapObjectCharacterTeamMissionModel`, создаваемая
  как `StaticConstructObject(класс, outer=станция)`: `RequestSelectMission`,
  `RequestSelectAuto`, `RequestStartMission`;
- сбор лута — `RequestMoveItemToInventoryFromContainer(сундук, false)` на
  `PalNetworkPlayerComponent` (тот же вызов, что «забрать всё» в игре);
- если UI-модель не заработает — фолбэк: `RequestSelectAuto_ServerInternal(0)` +
  `RequestStartMission_ServerInternal(0)` напрямую (для синглплеера).

## Команды (консоль UE4SS)

| Команда | Что делает |
|---|---|
| `exh scan` | все станции: состояние, миссия, база, координаты |
| `exh info <N>` | подробный дамп станции N |
| `exh chest <N>` | содержимое сундука станции N |
| `exh bases` | список баз (сверка имён) |
| `exh guild` | открытые миссии гильдии |
| `exh settings` | класс функций сортировки (нужен авто-подбору палов) |
| `exh ui <N>` | **главная проба**: UI-модель, чтения без/с репликацией |
| `exh missions <N>` | список доступных экспедиций станции N |
| `exh select <N> <id>` | выбрать миссию по id из списка |
| `exh auto <N>` | авто-назначение палов |
| `exh start <N>` | запуск экспедиции станции N |
| `exh remain <N>` | сколько осталось до финиша |
| `exh collect <N>` | забрать лут станции N в инвентарь |
| `exh collectall` | забрать лут со всех станций в состоянии Reward |
| `exh fb <N>` | фолбэк-путь (ServerInternal напрямую) |
| `exh help` | список команд |

## План теста (по шагам, лог присылать целиком)

1. Зайти в мир, где есть хотя бы одна станция экспедиций (любое состояние).
2. `exh scan` → сколько станций нашлось, верные ли базы/координаты.
3. `exh info 1`, `exh ui 1`, `exh missions 1` → главные пробы чтения.
4. На свободной (Ready) станции: `exh auto 1` → в логе «назначено палов: N»;
   затем `exh start 1` → state стал InProgress=2? Подойти к станции в игре и
   убедиться, что экспедиция реально бежит.
5. Когда какая-нибудь экспедиция завершится: `exh remain 1` (таймер),
   `exh chest 1` (лут в сундуке?), `exh collect 1` → предметы появились в инвентаре?
6. `exh collectall` — со всех станций сразу.
7. Если `exh auto/start` не сработали — `exh fb 1` (фолбэк-путь).
8. Выход в меню → повторный вход в мир → снова `exh scan` (проверка, что ничего
   не крашится и не висит между сессиями — главная болезнь мода с нексуса).

## Безопасность

- только вызовы нативных UFunction (ProcessEvent), без чтений по оффсетам;
- каждый вызов в `pcall` — ошибка не роняет игру;
- мод ничего не хранит между командами; UI-модель живёт одну команду и всегда
  останавливает репликацию (`RequestStopReplication`) перед освобождением.
