# ExpeditionHubTest v0.9 — менеджер экспедиций (Palworld 0.4.11, UE4SS Lua)

**F6 — панель. Полный цикл из панели: выбор миссии → назначение палов (вручную из
Palbox или АВТО) → запуск → сбор лута.** Игровой UI станции не открывается вообще.
Не для публикации (тестовая стадия).

## Что починлено в v0.9 (по итогам живого теста v0.8)

Тест v0.8: крашей больше нет, байты миссии совпали с ванильными байт-в-байт,
но выбор не сработал — `TargetMissionId=None`, а хук на нашем вызове показал
«архив не читается» (на ванильных вызовах — читается).

Разбор исходников UE4SS выявил **баг самого UE4SS** (LuaUObject.cpp,
`push_arrayproperty::lua_table_to_memory`): длина Lua-таблицы читается с
захардкоженного стек-индекса 1, поэтому массив, **вложенный в структуру-параметр**
(наш `{Bytes={...}}`), всегда передаётся **пустым**. (Этот же баг затирал
ref-указатель в `WriteBlackboard` — тот самый краш 0x70 в v0.7.)

Обход в v0.9 — «заёмный буфер»:

- путь с **TArray-userdata** копируется честно (поэлементный copy в исходнике);
- мод находит живой 1-байтовый массив у игрового объекта (кандидаты:
  `PalWorldMapUIData.CachedTextureRawData_ForV3Convert`,
  `PalGameSetting.BaseCampBuildingItemContainerTypes`,
  `PalGroupGuildBase.GuildChestAllowedRoles`,
  `PalMapObjectItemContainerModule.AllSlotAttribute`);
- рантайм-проверка размера элемента (запись 511 → чтение 255 = ровно 1 байт);
- содержимое объекта снимается ДО, восстанавливается СРАЗУ после вызова
  (сервер читает архив синхронно, внутри вызова);
- байты пишутся записью `ud[i]=v` (авто-растит массив), вызов идёт с
  `{Bytes=ud}`.

В логе при первом действии появится строка «буфер архива: Класс.Поле» — какой
кандидат сработал.

## Установка

```
Pal\Binaries\Win64\ue4ss\Mods\ExpeditionHubTest\
    enabled.txt
    scripts\main.lua
```

(перезапиши `scripts\main.lua`)

## Панель (F6)

- `<< PREV` / `NEXT >>` — выбор станции (все базы); инфо: состояние, миссия, база,
  палы, сундук, требование стихии, сила команды, % награды.
- Кнопки: **АВТО-ПАЛЫ** · **ЗАПУСК** · **СОБРАТЬ ЛУТ** · **СОБРАТЬ ВСЁ**.
- Блок списка, 3 режима (стрелки `<` `>` в шапке блока; клик по «РЕЖИМ: …» — обновить):
  - **МИССИИ** — экспедиции (сложность, время, сила, стихия×N, макс. палов), ВЫБРАТЬ;
  - **PALBOX** — палы по убыванию силы, «+ ДОБАВИТЬ» (помечены «на экспедиции»/«искл.»);
  - **НАЗНАЧЕНЫ** — состав станции, «− СНЯТЬ»; внизу «СНЯТЬ ВСЕХ», а при идущей
    экспедиции — «ОТМЕНИТЬ ЭКСПЕДИЦИЮ».
- `< СТР` / `СТР >` — страницы списка.

## Порядок теста

1. После загрузки мира в логе должны быть 4 строки «hook установлен».
2. F6 → выбери станцию (в инфо должно быть **Ready**).
3. Режим **МИССИИ** → **ВЫБРАТЬ** → в логе: «архив миссии (32 байт): …»,
   «буфер архива: …» и «ГОТОВО: миссия выбрана через архив»?
4. Режим **PALBOX** → **+ ДОБАВИТЬ** пала → «ГОТОВО: пал добавлен»?
5. **ЗАПУСК** → InProgress → при Reward → **СОБРАТЬ ЛУТ** → предметы в инвентаре?
6. Если что-то не сработало — пришли из лога строки «буфер: …», наши
   («архив миссии … / добавить пала: архив …») и хуковые («>>> [hook] …»).

АВТО работает стабильно (проверено в v0.7/v0.8) — им можно заполнять состав,
если вручную вдруг не пойдёт.
