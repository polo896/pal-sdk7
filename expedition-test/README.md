# ExpeditionHubTest v0.6 — менеджер экспедиций (Palworld 0.4.11, UE4SS Lua)

**F6 — панель. Полный цикл из панели: выбор миссии → назначение палов (вручную из
Palbox или АВТО) → запуск → сбор лута.** Игровой UI станции не открывается вообще.
Не для публикации (тестовая стадия).

## Что изменилось в v0.6 (починен краш выбора миссии + добавлены палы)

- **Починен краш при клике по миссии** (v0.5 падала `EXCEPTION_ACCESS_VIOLATION 0x70`).
  Причина: `RequestSelectMission` на живой HUD-модели станции рассчитан на открытое
  окно игры. В v0.6 на UI-моделях выполняются **только чтения** — ни одного вызова,
  меняющего состояние.
- **Все действия идут через серверные функции модели станции** (путь, подтверждённый
  живым тестом v0.3): выбор миссии, добавление/снятие пала, авто-заполнение, старт.
  Для функций с параметром `FPalNetArchive` мод передаёт архив Lua-таблицей
  `{Bytes={...}}` (поддержка подтверждена исходниками UE4SS-форка Palworld).
- **Байты архива для имени миссии сериализирует сама игра** — статической функцией
  `UPalActionTransportItem.WriteBlackboard(archive, имя)`. Запасной путь выбора —
  прямая запись поля `TargetMissionId`.
- **Байты архива для пала** (FPalInstanceID): 3 раскладки-кандидата, мод пробует по
  очереди и проверяет результат чтением списка назначенных. Неверные байты = тихий
  отказ сервера, не краш.
- **Этап палов как в игре**: до 100 слотов, у миссии показывается требование стихии
  (например `Ice 12/20`), рекомендуемая сила, макс. число палов, текущий % награды.
  Слабая команда = 0% награды — сортируй Palbox по силе.
- Список Palbox: только Palbox (партия и рабочие базы не подходят — их отклонит
  сервер), сортировка по силе пала, пометки «на экспедиции»/«искл.».
- **ЗАПУСК больше не затирает ручной состав** (в v0.5 авто-назначение выполнялось
  перед каждым стартом). АВТО — теперь отдельная кнопка.
- Пассивные хуки логируют все серверные вызовы экспедиций (и наши, и ванильные)
  с дампом байтов архива — сверка формата.


(перезапиши `scripts\main.lua`)

## Панель (F6)

- `<< PREV` / `NEXT >>` — выбор станции (все базы); инфо: состояние, миссия, база,
  палы, сундук, требование стихии, сила команды, % награды.
- Кнопки: **АВТО-ПАЛЫ** (авто-заполнение слотов) · **ЗАПУСК** (старт с текущим
  составом) · **СОБРАТЬ ЛУТ** · **СОБРАТЬ ВСЁ**.
- Блок списка с 3 режимами (стрелки `<` `>` в шапке блока или клик по «РЕЖИМ: …»):
  - **МИССИИ** — список экспедиций (сложность, время, сила, стихия×N, макс. палов),
    кнопка ВЫБРАТЬ у каждой, текущая подсвечена золотом;
  - **PALBOX** — твои палы, отсортированные по силе, кнопка «+ ДОБАВИТЬ»;
  - **НАЗНАЧЕНЫ** — текущий состав станции, кнопка «− СНЯТЬ», внизу «СНЯТЬ ВСЕХ».
- `< СТР` / `СТР >` — листать страницы списка (Palbox может быть большой).

## Порядок теста

1. F6 → полистай станции → режим **МИССИИ** (стрелка `>` в шапке блока) → список
   появился с требованиями (стихия×N, сила)?
2. **ВЫБРАТЬ** у миссии → в логе должно появиться «архив миссии (N байт): …» и
   «ГОТОВО: миссия выбрана …». Если сработала прямая запись — тоже ГОТОВО, но
   напиши, какая из двух.
3. Режим **PALBOX** → список палов с силой? (если сила «?» — пришли лог)
4. **+ ДОБАВИТЬ** сильного пала → «ГОТОВО: раскладка N работает (палов теперь X)»?
   Если «не сработало ни с одной раскладкой» — пришли лог целиком (там дампы байтов).
5. Добавь ещё 2–3 палов → в инфо станции смотри «стихия: … n/N» и «награда: X%» —
   растут?
6. **ЗАПУСК** → `state=InProgress`? Подожди таймер (или проверь позже).
7. При Reward → **СОБРАТЬ ЛУТ** → предметы в инвентаре?
8. Перезаходы в мир, открытие/закрытие панели много раз — крашей быть не должно.
9. (Опционально, очень полезно) подойди к станции и выбери миссию + добавь пала в
   игровом UI — в логе появятся строки `[hook] выбор миссии/добавить пала: …
   архив(N байт): …` — пришли их: это эталонные байты для сверки.
